- Swing auto-trading and Live trades are re-simulated deterministically from live swing_prices (src/lib/swing) and buy at the signal price (simulate liveEntry), backtests still at next open — why: no cron, shared logic, no missed live buys. Live trades only count signals on/after swing_settings "live_signals".start (₹10k each); swing_signal_log stores server seen/closed times plus first-seen entry_price/plan (immutable, ±8% check), fed back as simulate "fixed" — why: nothing backdated, live buys never vanish on refresh.
- Strategy regime stays an equal-weight index of the followed universe (unchanged so backtests stay reproducible); real indices + full NSE/BSE list live in swing_market_snapshot, filled by swing-market from Yahoo public quotes in 1,000-row rotating batches (pg_cron every 2 min in market hours) — why: broker search blocked, no free official feed.
- Custom and AI strategies are insert-only versioned JSON rules (rules.ts; swing_custom_strategies, swing_ai_strategies) — why: old backtests stay reproducible. AI versions adopted only if they beat the parent on the last 30% of history.
- Research pages share one ctxs/regime from MoneyDashboard; live "today" bar appended only after 9:15 IST weekdays.
- Desk controls: one shared swing_settings "controls" row, admin write, signed-in read.
- Real orders only via the swing-order edge function: admin-only, off by default, server-side limits, every attempt logged — why: browser can't skip limits.
- swing-ai-coach runs in chained steps using a copy of the engine in supabase/functions/_shared/swing — why: ~2s edge CPU limit; keep both copies in sync.
- The admin News & Research Centre composes existing content tools and reads paginated source records for IST reports; it verifies the admin role through the existing server RPC and labels legacy source leads as unverified — why: reuse publishing architecture without implying unsupported research or automation guarantees.
- Verified research/publishing automation lives in supabase/functions/news-automation: staged pipeline (audit→discover→dedupe→retrieve→verify→keywords→draft→checks→publish) with bounded units, leases and hourly cron ticks; evidence-gated (≥3 independent publishers incl. a primary official source, or a narrow official announcement) — why: nothing publishes without retrieved evidence; AI confidence alone is not verification.
- Firecrawl+Semrush are gateway-backed connectors called server-side only; publishing mode defaults to "review" (drafts held in news_drafts as pending for admin approval) — unattended auto-publish stays off until end-to-end checks pass.
- Sitemap: _shared/sitemap.ts is the single collector (sitemap-manager, sitemap-xml, news-automation import it); lastmod is page-authoritative or omitted, never generation time — why: honest timestamps; cron 'news-sitemap-refresh' runs 10:00/22:00 IST, 'news-automation-tick' hourly 06:30–22:30 IST inside the configured window.
- Scheduled callbacks authenticate with the x-cron-secret header checked against public.news_cron_secret (never the service key); cron.job headers read it via subquery so the value is never stored in plaintext.
